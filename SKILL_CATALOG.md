# Canonical Skill Catalog

`pvnkmnk/AgenticSelfHostSkills` is the canonical repository for reusable agent **behavior**. It is the renamed continuation of the repository formerly addressed as `pvnkmnk/agent-skills-library`; GitHub redirects the former path to this repository. Product repositories should link to shared skill behavior rather than copy it.

> Keep host-specific configuration, service desired state, secret contracts, and environment-specific runbooks outside this catalog. Skills may require explicit confirmation, but they must never embed secret values or silently obtain production write authority.

## Authority Boundaries

| Concern | Canonical home | Catalog treatment |
|---|---|---|
| Reusable behavior, safety rules, decision workflows, and portable validation helpers | This repository | Maintain as versioned skill trees under `skills/<skill-name>/`. |
| Private WSL setup, `dotctl`, Television, and operator runbooks | [`pvnkmnk/dotfiles`](https://github.com/pvnkmnk/dotfiles) | Link when a skill needs the control-plane contract; do not duplicate host instructions. |
| Service topology, Proxmox desired state, support matrix, and recovery evidence | [`pvnkmnk/homelab-proxmox-ansible`](https://github.com/pvnkmnk/homelab-proxmox-ansible) | Link when a skill needs a system-of-record; do not carry mutable deployment configuration. |
| Secret values and machine credentials | Bitwarden Secrets Manager and approved host-local storage | Document narrow retrieval/rotation rules only; never commit values, tokens, rendered environments, or private keys. |
| Portfolio decisions, approvals, and work status | Linear and the private decision record | Reference decisions where needed; do not treat a skill as an approval record. |

## Admission and Deprecation Rules

1. Promote a candidate only when it is reusable across more than one repository or environment, has clear trigger metadata, and contains no secret, private-host, or live-vault material.
2. Merge incremental value into an existing canonical skill rather than creating synonymous skills.
3. Localize host-specific content in `dotfiles` or `homelab-proxmox-ansible` as a runbook, contract, or reference.
4. Quarantine untested, credential-dependent, destructive, or unclear skills until they have a bounded review and a safe representative validation.
5. Record source repository, commit, and validation evidence for every promoted skill. Remove generated files such as `__pycache__` and `.pyc` from skill trees.
6. Retire duplicate source repositories only after their provenance is recorded and no unique acceptance criterion remains.
